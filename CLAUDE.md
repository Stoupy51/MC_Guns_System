# MC Guns System

Minecraft 26.3 datapack and resource pack, generated by StewBeet (beet) from `src/`.
`build/` is the output: tracked in git, never edited by hand.

## Commands

```bash
uv sync                                       # Python 3.14, StewBeet, ruff, pyright
uv run stewbeet                               # build
uv run python scripts/verify.py baseline      # snapshot build/ before a change
uv run python scripts/verify.py check --diff  # rebuild, show what changed (comments ignored)
uv run python scripts/verify.py validate      # mecha parse, missing and unreachable resources
uv run python scripts/verify.py server --java /abs/path/to/java25   # real 26.3 server load
uv run python scripts/verify.py lint          # ruff, pyright strict, complexipy <= 15
```

In game: `/reload`, `/function mgs:config`, `/function mgs:_give_all`.

A refactor must leave `check` empty. A behaviour change shows in `check` and only where intended.

## Layout

- `src/setup_definitions.py`: items. `src/link.py`: every function, in dependency order.
- `src/config`: stats and catalogs. `src/database`: item builders, camo, models.
- `src/functional/<domain>`: one package per system (weapon, core, progression, zombies, multiplayer, missions, map_editor, shaders).
- `specs/`: planned features; the inbox at the bottom of `specs/README.md` takes loose notes.

## Conventions

- Functions are written with `write_versioned_function("path", f"""...""")` (`mgs:v<version>/path`). Inside f-strings, NBT braces are doubled.
- StewBeet turns every literal text component into a lang key built from its words: changing a message changes `en_us.json`.
- Comments say why, in at most two lines; no paraphrase of the next command, no history.
- No em dash, ellipsis, arrows, multiplication sign or box drawing in code, comments or texts (`stouputils check` lists them). `➤`, `◀ ▶` and the HUD glyphs are fine.
- Dataclasses over tuples; pyright strict; `uvx --from stouputils stouputils check src` clean.
- Prefer `type=` on `@e` selectors in anything reached from `#minecraft:tick`.

## Frozen identifiers

These live in players' worlds. Renaming one needs a migration and the author's approval:

- scoreboard objectives (`mgs.*`, `load.status`), teams `mgs.*`, bossbars `mgs:pu_*`, the trigger `mgs.player.config`;
- storages `mgs:maps`, `mgs:multiplayer`, `mgs:zombies`, `mgs:missions`, `mgs:config`, `mgs:data`, `mgs:signals` and `mgs:gun`;
- entity tags `mgs.*`, above all `mgs.element.*` and `mgs.map_element` on saved map editor markers;
- item `custom_data.mgs.*` and `custom_data.smithed.*`, loot tables `mgs:i/<id>`, item models `mgs:<id>`;
- advancements `mgs:challenges/**` (unversioned on purpose);
- public functions (`mgs:_give_all`, `mgs:config`, `mgs:mob/default/level_*`, `mgs:zombies/bonus/*`, `mgs:zombies/recover`) and function tags `#mgs:*`;
- scheduled functions (pending ones are saved in `level.dat`) and the commands stored in map data (`start_commands`, `respawn_commands`, enemy `function`).

## Linux checkout quirks

- 312 media files under `build/` are committed as symlinks (mode 120000) and show as modified after a build. Never commit them:
  `git ls-files -s build | awk '$1=="120000"{print $4}' | xargs git update-index --assume-unchanged`
- `minecraft_source_code` is a git link with no `.gitmodules` entry, so a fresh clone gets it empty.
